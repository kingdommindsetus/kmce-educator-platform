# Pegasus Full Deployment Plan — Oct 2

This plan freezes repo discovery and turns the selected systems into one governed company operating model.

## Architecture rule
Pegasus owns orchestration, policy, approvals, tenant state and evidence. Repositories provide capability patterns, adapters or services; they do not become independent sources of truth.

## Layer 1 — Founder / Executive
- Simon: executive reasoning and delegation
- Marie: operations and service coordination
- Plane patterns: work visibility
- Command Center: founder status, approvals, blockers, verified KPIs

## Layer 2 — Workflow / State / Tools
- Pegasus task contract
- Neon operational state
- Activepieces workflow patterns
- Composio authorized external connectors
- Hermes/ECC runtime/skills where useful
- Audit/evidence records for every task

## Layer 3 — Customer / Doctor Operations
- Chatwoot: conversation/inbox model
- Documenso: agreement/signature integration pattern
- Booker: scheduling
- Echo: outreach and qualification
- Marie: onboarding and exception handling

## Layer 4 — Marketing / Creative
- Growth OS + digital-marketing-pro: grounded strategy
- GTM assistant: campaign research
- ThreadForge: content
- Penpot: design system/prototypes
- Canva Developer Agent Kit: branded editable assets
- InvokeAI: image generation/refinement
- Voicebox: authorized TTS/voice
- YouTube agent: video workflow
- Ayrshare/BrightBean/Pinterest agent: distribution
- listmonk: controlled newsletters/campaign email

## Layer 5 — Commerce
- Shopify AI Toolkit + Shopify skills
- Medusa patterns
- Printify adapter
- Alice owns commerce QA and proposed actions
- Pegasus gates publish/delete/price/destructive changes

## Layer 6 — Verification
- Phoenix observability
- Promptfoo regression/red-team
- DeepEval quality evaluation
- Argent UI/application verification
- IRIS aggregates health and evidence

## Oct 2 delivery sequence

### P0 — Must work
1. Command Center loads and clearly shows queued/running/waiting approval/failed/complete.
2. Task/event/evidence model is real, not simulated.
3. Simon can create/route a task to at least one specialist and receive evidence back.
4. One doctor/client workflow completes end-to-end with a visible handoff.
5. Approval gate blocks unauthorized external actions.
6. Founder sees failures/blockers.
7. Verified metrics show source/as-of context.

### P1 — Demonstrate coherent departments
1. Echo → Booker conversation/scheduling handoff.
2. Mark/Cammy → Evan/Lucy campaign handoff.
3. Alice storefront/commercial audit and proposed action.
4. Marie doctor onboarding/document checklist.
5. IRIS verification record attached to completed work.

### P2 — Post-launch hardening / service deployment
1. Deploy/self-host or connect Plane if needed.
2. Connect Chatwoot as shared inbox.
3. Connect Documenso via API/licensed deployment.
4. Connect listmonk for real campaigns.
5. Connect Penpot MCP/API for design flow.
6. Connect Canva MCP/SDK capabilities that are actually available.
7. Provision InvokeAI compute if image generation is needed at scale.
8. Provision Voicebox locally/secure compute for approved voices.
9. Add tenant isolation/RBAC and per-client credentials before external client rollout.

## What is explicitly not in Oct 2 critical path
- Forking all upstream repositories into Pegasus.
- Running every upstream service on the same Vercel app.
- Unreviewed AGPL/copyleft source embedding.
- GPU-heavy InvokeAI deployment inside the primary web app.
- Unconsented voice cloning.
- Autonomous outbound sends or live publishing without policy gates.

## Launch definition
Oct 2 launch means the company can visibly execute governed AI work end-to-end with real state, evidence, approvals, handoffs and verified business data. It does not mean every selected upstream service is fully deployed on day one.
